# Update the data sources index

`docs/data_sources_index.json` is a lightweight catalog of every standardized
data source in this repo. It is **regenerated by `scripts/build_docs.R`**, which
runs automatically every day and on every `measure_info.json` change.

**Five hand-editable fields — `name`, `summary`, `search_terms`, `bucket` (all
per dataset) and `dataset_stratification` (per file) — are preserved across
rebuilds.** `build_docs.R` reads the existing `docs/data_sources_index.json`
and keeps whatever is already in those fields, so **you can edit them directly
in the JSON and they will not be overwritten.** Every other field
(`github_folder`, `data_url`, `data_dictionary`, `latest_date`, and the
`files[]` links) is always recomputed, so editing those is pointless — fix the
source data instead.

Defaults for a **brand-new** dataset/file with no text yet:
- `name` → `_sources[].name` from `measure_info.json`.
- `summary` → a concise extractive summary (first sentence of the source's
  `_sources` description).
- `search_terms` and `bucket` → both default to the human-readable labels of
  the bundles that consume the source (`bundle_chronic_diseases` → `"Chronic
  diseases"`). They start out identical but are two separate fields — edit
  each independently afterward. `search_terms` is meant for search-box
  keywords (can accumulate more terms than just bundle names); `bucket` is the
  grouping shown for site navigation.
- `dataset_stratification` → a value from `resources/stratification_cache.json`
  (keyed `"<dataset>/<filename>"`) if present, otherwise a blurb derived from the
  file name.

Re-deriving a preserved field: for `name`/`summary`/`dataset_stratification`,
blank the value and rebuild. For `search_terms` or `bucket`, **delete that
field entirely** — an empty `[]` is respected as an intentional "none" and is
not re-derived (so clearing one sticks; edits are never clobbered by bundle
changes). Deleting one of the two does not affect the other.

So the caches/fallbacks only fill the gap on first appearance; once real text is
in the JSON, that text wins and persists.

## Fields in each dataset entry

`build_docs.R` derives these automatically (no action needed):

| Field | Source |
|-------|--------|
| `dataset` | source folder name under `data/` |
| `github_folder` | link to the source folder on GitHub |
| `data_url` | first `_sources[].url` |
| `data_dictionary` | `https://pophive.github.io/Ingest/#<section-id>` |
| `latest_date` | most recent date found across the source's standard files |
| `files` | one entry per `standard/*.csv.gz` (single- and multi-file alike), each with `dataset_link` (direct raw link) and `dataset_stratification` |

The hand-editable fields:

- **`name`** — display name (defaults to the `measure_info.json` source name;
  override when one source dir needs a more specific label — e.g. the `epic_*`
  datasets, which otherwise all read "Epic Cosmos").
- **`summary`** — one to two plain-English sentences describing the dataset.
- **`search_terms`** — array of search-box keywords, derived from bundle
  membership by default; edit to add, remove, or rename, and feel free to add
  extra keywords beyond bundle names (disease names, source organization, etc.).
- **`bucket`** — array of the bundle label(s) this dataset is grouped under
  for site navigation, derived from bundle membership by default; edit
  independently of `search_terms` even though they start identical.
- **`dataset_stratification`** (inside each `files` entry) — a short phrase
  describing how that file is stratified **beyond time and geography**.

## Procedure

### 1. Find what needs text

From the repo root, list source folders (everything in `data/` that is not
`bundle_*` and has both a `measure_info.json` and at least one
`standard/*.csv.gz`). Then open the current `docs/data_sources_index.json`:

- A dataset needs a **summary** if its `summary` is missing, empty, or is just
  the extractive fallback (i.e. reads like the raw first sentence of the source
  description rather than a purpose-written 1-2 sentence blurb).
- A dataset needs **stratification** text if any file's `dataset_stratification`
  is missing or is a placeholder — a filename-derived `"Stratified by <tokens>."`
  or the single-file `"Overall; no stratification beyond time and geography."`.

Default when a new dataset is added: only fill what's missing/placeholder; leave
good existing text alone. If the user asks to refresh a dataset, rewrite it.

### 2. Write the summary (1-2 easy-to-read sentences)

Read `data/<dataset>/measure_info.json` and use the `_sources` `description`
field(s) — consider all entries under `_sources`, since multi-source datasets
(e.g. `nchs_mortality`) cover several distinct things. Write **one to two
sentences** describing what the dataset contains, suitable for a data catalog:
no preamble, no quotes, no markdown.

Write at roughly a **15-year-old reading level** — short sentences, everyday
words, and one idea per sentence. Spell out or briefly explain jargon and
acronyms the first time they appear (e.g. "ED (emergency department) visits"
rather than bare "ED visits"; "de-identified (no names or personal details)"
rather than bare "de-identified"). Cut methodology detail that doesn't help a
general reader decide whether the dataset is useful to them (exact model
names, internal program acronyms, survey-instrument citations) — save that
level of detail for `measure_info.json`, not the catalog summary.

Put it **directly in `docs/data_sources_index.json`** as that dataset's
`summary` value. It is preserved on rebuild.

### 3. Write stratification blurbs for every file

For **each** `standard/*.csv.gz` of a dataset (single- and multi-file alike),
write a short sentence describing what that file contains and how it is
stratified **beyond time and geography**. Infer it from the file name and the
column headers — the non-`time`/non-`geography`/non-value columns (e.g. `age`,
`sex`, `race_ethnicity`, `serotype`, `vaccine`, `virus`, `grade`) are exactly the
stratification; the measure columns say what is measured. Read a file's header
with `vroom::vroom(path, n_max = 0)`. Keep each blurb to **one brief sentence**
(aim for well under 20 words) — name the stratifying dimensions plainly, skip
qualifiers and background that belong in the dataset `summary` instead.

- **Multi-file datasets:** describe what distinguishes each file.
- **Single-file datasets:** replace the `"Overall; no stratification beyond time
  and geography."` placeholder with a real sentence. Many single-file sources
  *do* have stratifiers (e.g. `nccr` by cancer type/age/sex/race; `nssp` by
  virus) — don't leave the placeholder just because there is one file. If a file
  genuinely has no dimension beyond time and geography, describe its measure
  instead (e.g. `measles_cdc/data.csv.gz` → `"Weekly measles case counts."`).

Examples:
- `nchs_mortality/data_state_21_causes.csv.gz` → `"Age-adjusted mortality rates for 21 selected causes of death (state-level)."`
- `narms/data_resistance_agent.csv.gz` → `"Human isolate resistance by bacterial genus/serotype and individual antimicrobial agent (with CLSI class)."`
- `nccr/data.csv.gz` → `"Childhood cancer incidence by cancer type (ICCC site), age group, sex, and race/ethnicity."`
- `nssp/data.csv.gz` → `"Percentage of emergency department visits for RSV, influenza, and COVID-19, by virus."`

Put each blurb **directly in the file's `dataset_stratification`** in
`docs/data_sources_index.json` (preserved on rebuild). For a dataset that has
**no** JSON entry yet, you can instead pre-seed
`resources/stratification_cache.json` (keyed `"<dataset>/<filename>"`) so the
first build picks it up.

### 4. Regenerate the index

From the repo **root** (not `docs/`):

```powershell
Rscript scripts/build_docs.R
```

This rewrites `docs/index.html`, `resources/data_manifest.json`, and
`docs/data_sources_index.json`, keeping the `summary` and
`dataset_stratification` text you wrote and recomputing every other field. No
API key is required.

### 5. Verify

Open `docs/data_sources_index.json` and confirm each affected entry has a
purpose-written `summary`, sensible `search_terms`/`bucket`, and a `files`
array whose entries each have a `dataset_link` pointing at a real
`standard/*.csv.gz` and a meaningful `dataset_stratification`. Report which
datasets were added or refreshed.

## Notes

- The GitHub raw base is `https://raw.githubusercontent.com/PopHIVE/Ingest/main`;
  links look like `.../main/data/<dataset>/standard/<file>.csv.gz`.
- Commit the regenerated `docs/data_sources_index.json` (and
  `resources/stratification_cache.json` if you seeded it) together with the rest
  of `docs/` and `resources/data_manifest.json`.
- One-time reseeding trick: if the JSON holds a placeholder you want a cache
  value to override, delete `docs/data_sources_index.json` before running the
  build so the cache/fallback repopulates it. Summaries have no cache, so only
  do this after the summaries you want are safely in the JSON (or you'll drop
  back to the extractive fallback).
